# ui rules

The shadcn component library and the design tokens of the whole product. Auto-loaded under `packages/ui/`. How features consume the primitives (which one to reach for, layout-only `className`): `apps/app/CLAUDE.md`. Cross-cutting rules: `/CLAUDE.md`.

## Layout

```
src/
  components/ui/<name>.tsx   one primitive per file (shadcn and house primitives side by side)
  libs/                      `utils` (`cn`)
  styles/globals.css         the only place tokens live: `:root` / `.dark` variables and `@theme inline`
components.json              shadcn config (style new-york, lucide, neutral base)
```

`exports` map: `./globals.css`, `./components/ui/*`, `./libs/*.js`. Consumers import `@packages/ui/components/ui/<name>`; there is no barrel.

## Rules

1. **Look lives in the theme or the primitive, nowhere else.** Colors, typography, radius, shadows and look-defining padding are tokens in `globals.css` or variants (`cva`) inside the primitive. **Why**: a design change must be one edit; a style hard-coded in a feature is a fork of the design system.
2. **shadcn-pure.** Use the real component and its real slots; do not override `data-slot="*"` from outside, and do not add wrapper variants in a feature. An adjustment is made in the theme or in the primitive itself, and a missing capability becomes a new primitive here, never inline in a feature. Copy a neighbouring primitive's shape (variants through `cva`, `asChild` for composition).
3. **A primitive holds no copy of its own.** Text it renders (a dialog's sr-only close label, a password reveal toggle's name, a cancel button) is a **required prop** the app fills through `t()`, typed so a call site that renders it cannot omit it (`closeLabel` on the dialog is the reference). **Why**: a primitive that shipped an English default would put that literal in every locale's DOM with no diff to catch it.
4. **Typography goes through `typography.tsx`** (named exports: `TypographyH1` with `variant="page"`, `TypographyInline`, ...). A new text style is a variant there, not a class string in a feature.
5. **Page width is `pageContainerVariants({ width })`**, declared by every page: `full` (the whole screen, cards and lists that reflow into more columns), `reading` (a 70 character measure, pages of running text and focused flows), `form` (a lone form or message), `wide` (the home's own grid), `sheet` (the printed planner's preview), `landing` (the site). All share the fluid `--page-gutter`, which the app bar uses too, so everything lines up at any width. Cards of a `full` page go in `CardColumns` (uneven heights, multi-column so reading and tab order stay the source order; a masonry grid ships only in Safari in 2026) or `CardGrid` (similar cards in rows), grouped by `PageSection` and reached from a `SectionNav`. A new width is a new variant, never a hand-picked `max-w-*` at a call site (`apps/app/src/__tests__/page-width.test.ts` fails on one).
6. **Color tokens are measured, not eyeballed.** Foreground/background pairs must hold WCAG AA contrast (4.5:1 text) in light and dark, in every palette; the tokens whose value was tuned carry the measurement in a comment in `globals.css`, and `packages/web-kit/src/theme/__tests__/palette-contrast.test.ts` recomputes the critical pairs from the file. **Why**: the accessibility gate fails the PR on a `serious` contrast violation but only audits the default palette, so a token change is verified before it ships.
7. **An interactive primitive ships its keyboard contract**: focus order, trap and restore, Escape. The interaction spec in `apps/app/a11y/` is where it is asserted (`apps/app/CLAUDE.md`, "Accessibility gate"). The tour is the one non-modal overlay: it takes focus on its primary control, Tab past its last control lands on the highlighted element instead of looping, Escape closes it for good, and focus goes back to where it was before it opened (`apps/app/a11y/tour.spec.ts`). **Why**: a guide that traps focus blocks the very element it points at.
8. **The package ships source**, like every private package (root rule 4): no build step, `exports` point at `src/`.
9. **Every look value is named by its role, and the set is closed.** The Tailwind size scales (`rounded-md`, `shadow-lg`) are removed from `@theme` so they no longer compile; a primitive picks a role:
   - **Radius**: `rounded-mark` (case, code, mark), `rounded-inner` (any block or field), `rounded-popover` and `rounded-surface`, both computed as inner + their padding so a block laid inside is concentric by construction, `rounded-full` (buttons, chips, tabs, avatars, icon tiles).
   - **Padding**: `p-surface` on every surface (card, panel, dialog, sheet, drawer, empty), `p-block` on every block inside one, `p-popover` in menus; a card stacks its parts 12px apart.
   - **Heights**: `h-control-sm`, `h-control`, `h-control-lg`, one token per pointer (coarse 32, 44, 52; fine 28, 36, 44). A `sm` control keeps its look and gets an invisible 44px hit area under a finger, never a visual grow.
   - **Icons**: `size-icon-sm`, `size-icon`, `size-icon-lg` (14, 16, 20) set by the primitive through `[&_svg]` (an unsized icon falls back to 16, never the library's 24), `size-icon-mark` (8) only for a mark's dot, one stroke (`--icon-stroke`); an icon is imported by concept from `icons.ts`; an icon standing for a row, an empty state or a step sits in `IconTile`.
   - **Type**: `text-display`, `text-title`, `text-heading`, `text-body`, `text-small`, `text-meta`, each with its line height (titles add `font-display`, never `leading-none`); off scale only the DateTab digits, the site hero title and `text-2xs` in the 20px avatar.
   - **Borders**: a block inside a surface has no border, only a fill (`surface-container` or the child's tint); a border on a block is a state at 2px (`border-warning-edge` urgency, `border-destructive` overdue or error at one opacity, selection, today, drop target), the same token in light and dark. A coloured band (a child's edge, the app bar's top, a printed card's head) takes `--stripe-width`, never a third width.
   - **Elevation and motion**: `shadow-rest` (lying on the page), `shadow-raised` (lifted by hover or selection), `shadow-float` (opened above the page); a movement takes its curve and duration from the motion tokens, the spring reserved for the answer to a deliberate gesture, with a still counterpart under reduced motion.

   A new role token is also registered in `cn` (`libs/utils.ts`), or the class merge drops it beside a colour. Three guards hold the set closed: `src/__tests__/design-system.test.ts` scans the sources (arbitrary look values, the removed scales, icon sizes and strokes, mark dots, border widths, control heights, look classes in apps, inline styles outside its named list of run time values), `palette-contrast.test.ts` measures the edges (field, focus, urgency, overdue) on every paper and child tint, and `apps/app/a11y/visual-system.spec.ts` measures the rendered icons, control heights and nested corners. A value no token names becomes a token, never an exception. **Why**: two surfaces that pick their own corner, padding, height or shadow read as two products; a value named by role leaves one place to tune.
10. **A palette re-inks the paper and may move a child out of its action's way, never change what a colour means.** It sets the surface, ink, border, action and shadow tokens, in a light block and a dark block holding the same keys; categories, urgency and alerts stay shared. The action colour marks only action, current position, block title icons, progress, focus and the one hero block, never a child, a category, urgency or an alert. **Why**: a dark block missing a key silently inherits the light value (the light palette rule comes later than `.dark`). The 16 child colours are declared on `:root, [data-palette]` so a preview never inherits the page's shifts; a palette whose frank action falls in a child's family restates only that child, nudged in lightness or by a few degrees so it keeps its name, instead of dulling the action. **Why**: a coloured action sharing a child's family makes that child's cards read as buttons. `palette-contrast.test.ts` refuses, in every palette and mode, two colours of one family (under 30° of hue) closer than OKLab ΔE 0.1: a child against the action, the secondary surface, the urgent amber or the alert red, two children against each other, and the action against the amber or the red; the action-tinted hero surface (`primary-container`) stays under 0.03 of chroma so it never reads as a child's card, and two light palettes differ by at least ΔE 0.1 summed over their page and their action, so no two look alike.
11. **A tile's place and size are written by the grid that holds it alone; a tile's own effects play on its inner panel.** The read grid places tiles through its CSS variables, the grid engine of the arranged home through its own inline style; our CSS only times the engine's moves (the reflow transition of `dashboard-edit`) and never sets a position, size or transform on the frame. A lift, a shadow or an entrance plays on the panel inside. **Why**: two writers on one frame fight, and the home's invariant (every block on the same rectangle within 1 px, read or arranged, `apps/app/a11y/home-grid.spec.ts`) only holds while one grid alone draws the frame.

## Commands

`pnpm icons:generate` (every PNG icon of the app, from `src/assets/public/favicon.svg`: run it in the change that touches the mark or its tile colour, never edit a PNG by hand) · `pnpm ui:add <component>` (root script, runs `shadcn add` inside this package), then `pnpm --filter @packages/ui ui:fix-imports` (shadcn writes `/src/...` and `from "cn"` import paths the package cannot resolve) · `pnpm --filter @packages/ui type-check`. Check the shadcn registry before writing a custom primitive.
