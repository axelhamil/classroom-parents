# school-calendar rules

School holidays and bank holidays of the calendar a parent chose: a country, a region of it, and where the school holidays come from (`GET /school-calendar?from&to`, `GET /settings`, `GET /regions`, `GET /preview`, `PUT /choice`, `POST|DELETE /periods`, `POST /periods/import`). Module contract: `modules/CLAUDE.md`.

## Invariants

1. **The official calendars are read by the server only**, through `ISchoolCalendarSource`: France from data.education.gouv.fr `fr-en-calendrier-scolaire` and calendrier.api.gouv.fr (Licence Ouverte 2.0), school holidays of other countries from OpenHolidays (ODbL), their bank holidays from Nager.Date v4 (public days only). `domain/calendar/coverage.ts` says which source covers which country. **Why**: the app's CSP `connect-src` lists the api alone, and one cached read serves every parent of a region.
2. **Every read goes through the cache table** (`school_calendar_cache`, one row per source feed and period): fresh for 7 days, then refetched; when the source fails, the last copy is served however old, and only a miss without any copy is `SCHOOL_CALENDAR_UNAVAILABLE`. Writing the cache is bookkeeping, not a state change: no event.
3. **A period runs from its first to its last day off.** French rows give `end_date` as the day classes resume (except a one-day bridge) in Paris time, teacher-only rows dropped; OpenHolidays `endDate` is inclusive; an iCalendar `DTEND` is exclusive. Change a mapping only with its adapter test.
4. **No choice, no calendar**: a parent who never chose gets `choice: null` and empty lists, never a default country. The parent's country preference (`IParentPreferences`, bound by the host) and the French academy list only propose; neither is stored. "I don't know" is a choice: bank holidays show, school holidays do not.
5. **A region matches a row by exact code or by prefix** (`CH-GE` matches `CH-GE`, `DE-BY` matches `DE-BY-AU`); rows without region apply to the whole country. A country whose school holidays are not published (`schoolHolidaysCovered: false`) is announced, never silently empty.
6. **Own periods belong to the parent**: typed (`manual`) or imported (`ics`) into `school_holiday_period`; a new import replaces the earlier `ics` rows and keeps the typed ones. Ownership sits in the repository `WHERE`: another parent's period is `SCHOOL_CALENDAR_PERIOD_NOT_FOUND`.
7. **An iCalendar file is data, never code**: `readIcsPeriods` keeps all-day events only, skips cancelled ones, expands no recurrence, and caps 512K characters, 1000 events, 200 periods; names are stripped of control characters. **A link is fetched by `SafeIcsDownloader` only**: https, no credentials nor port, every resolved address public (`@packages/http/private-ranges`), no redirect, 5 s, 512 KB streamed cap, behind the host's per-user `icsImportRateLimit`. **Why**: the server fetches a URL a user typed, the classic SSRF. The link is not stored.
8. **Every write emits in its unit of work**: `school_calendar.choice.changed` (`userId`, `country`, `region`, `source`, nulls when cleared; nothing when the value is already in force) and `school_calendar.holidays.edited` (`userId`, `change`, `origin`, `periods`). The choice and the periods cascade with the user (RGPD wipe) and are part of the data export.

## Composition

The api composes this module in a container of its own (`apps/api/src/composition/school-calendar.ts`) and binds `IParentPreferences` to the assistant's preferences; `FAKE_PROVIDERS=1` overrides the source with `src/testing/fake-school-calendar.source.ts` (French zone B, Geneva, Moroccan bank holidays).
